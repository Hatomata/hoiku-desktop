# 保育指導案・実習記録 作成ツール(デスクトップ版)

ブラウザではなく、パソコンに**インストールして使うアプリ**です。

- 入力した内容は**自動的に、パソコン内のフォルダにファイルとして保存**されます
- **自動バックアップ**も同じフォルダに残ります(ブラウザの履歴削除では消えません)
- インターネットなしで使えます(Excel出力も含む)
- 新しいバージョンを公開すると、**インストール済みのアプリが自動で更新**されます
  (毎回ビルドしたり、インストールし直したりする必要はありません)

## 保存されるもの(保存フォルダ)

初期設定では、次のフォルダに保存されます。

```
ドキュメント\保育指導案・実習記録\
├─ 教育実習1.json            ← プロジェクト1つにつき1ファイル(常に最新の内容)
├─ 保育実習1.json
└─ バックアップ\
    ├─ 教育実習1\
    │   ├─ 20261005_101500.json   ← 自動バックアップ(日時つき)
    │   └─ 20261005_094200.json
    └─ 保育実習1\ …
```

- アプリ内の「**保存フォルダを開く**」ボタンで、このフォルダをエクスプローラーで開けます。
  「保存フォルダを変更」(起動時の画面)で、別のフォルダ(OneDrive・USBメモリなど)にも変更できます。
- プロジェクトのファイル名は、プロジェクト名に合わせて自動で付きます(名前を変えるとファイル名も変わります)。
- **入力すると数秒で自動保存**されます。ウィンドウを閉じるときも、その時点の内容を保存してから閉じます。
- **バックアップ**は、作業中は約10分ごと(内容に変更があったときだけ)と、「今すぐ保存」を押したときに作られます。
  古いバックアップは自動で整理され、「直近30個」と「過去30日分の各日の最後の1つ」が残ります。
- プロジェクトを削除すると、ファイルは**ごみ箱**に移動します(バックアップは残ります)。

### バックアップから戻したいとき

1. プロジェクトを開いた状態で「**バックアップを見る**」を押します。
2. 戻したい日時のファイルを、ひとつ上の「保存フォルダ」にコピーします。
3. アプリの起動画面(「既存のプロジェクトを開く」)に、別のプロジェクトとして表示されます。

### いままでのデータを引き継ぐ

ブラウザ版・インストール版(PWA)で「プロジェクトを保存」して作ったJSONファイルを、
そのまま**保存フォルダにコピー**するか、アプリの「データ読み込み」で読み込んでください。

## 最初の導入(1回だけ)

### ① GitHubにファイルを置く

1. https://github.com にログインし、右上の「+」→「New repository」で新しいリポジトリを作ります
   (名前の例: `hoiku-desktop` / **Public** を選びます)。
2. 「uploading an existing file」から、**このフォルダの中身すべて**(`.github` フォルダを含む)を
   ドラッグ&ドロップして「Commit changes」を押します。
   - `.github` フォルダが見えない・入らない場合は、「Add file」→「Create new file」で
     名前欄に `.github/workflows/release.yml` と入力し、ファイルの中身を貼り付けてください。

### ② インストーラーを作る(GitHubが自動でやってくれます)

1. リポジトリの「Actions」タブを開きます(初回は有効化のボタンが出たら押します)。
2. 左の一覧から「**リリース**」を選び、「Run workflow」→「Run workflow」を押します。
3. 5〜10分ほど待つと、リポジトリの右側「Releases」に、
   `保育指導案・実習記録 Setup 1.0.0.exe` が公開されます。

### ③ パソコンにインストールする

1. 上の `.exe` をダウンロードして実行します。
2. 「WindowsによってPCが保護されました」と出た場合は、「詳細情報」→「実行」を押します
   (個人で作ったアプリで、有料の署名をしていないための表示です)。
3. デスクトップにアイコンができます。

## 新しいバージョンを配る(更新のたび)

更新には2種類あります。**日々の更新のほとんどは、①の「画面だけの更新(パッチ)」で済みます。**

### ① 画面だけの更新(パッチ)― インストーラーを作らずに配る

`renderer/index.html`(画面)だけを変えたときの方法です。ビルドも「Run workflow」も要りません。

1. `renderer/index.html` を新しい内容に差し替えます。
2. ファイルの先頭近くにある `<meta name="ui-version" content="1.0.0">` の数字を上げます(例: `1.0.1`)。
   **数字が同じままだと配られません。**(この行と、すぐ下の `min-app-version` の行は消さないでください)
3. GitHubの同じ場所(`renderer/index.html`)に上書きアップロードして「Commit changes」を押します。

これだけです。インストール済みのアプリは、起動して8秒後と、その後1時間ごとに、GitHub上の
`renderer/index.html` を確認し、画面の版が新しければ小さなファイルとして受け取ります。
受け取ると、画面下に「画面の更新(バージョン○○)を受け取りました」と表示されます。
「今すぐ反映」を押すとすぐに切り替わり、押さなくても次回の起動時に自動で切り替わります。
(反映の前に、入力中の内容は自動で保存されます)

**安全のための仕組み**

- 途中で切れたファイルや、この画面ではないファイルは、受け取りません。
- 新しい画面が正しく起動できなかったとき(読み込みの失敗、異常終了、15秒たっても「起動完了」の報告がない)は、
  **自動で、アプリに入っている元の画面に戻り**、その版は二度と使いません。
  原因を直したら、`ui-version` をさらに上げて配り直してください。
- `min-app-version` は「この画面を動かせる、いちばん古いアプリのバージョン」です。新しい画面が
  アプリ本体の新しい機能(②で配るもの)を必要とするときだけ、その機能を含むアプリのバージョン
  (`package.json` の `version`)に上げてください。それより古いアプリには画面が配られず、
  アプリ本体の更新が届いたあとで反映されます。
- ②でアプリ本体を更新して、その中の画面が、すでに受け取っているパッチと同じか新しい場合は、
  パッチは自動で使われなくなります。
- 画面のパッチは、GitHubの `renderer/index.html` の内容がそのまま配られます。GitHubのアカウントに
  第三者が入れないよう、2段階認証をおすすめします。
- パッチが働くのは、インストールしたアプリだけです(`npm start` では働きません)。

### ② アプリ本体の更新(インストーラー)

`main.js` / `preload.js` / `storage.js` / `patcher.js` / `package.json`(使うライブラリを含む)
を変えたときの方法です。

1. ファイルを更新します。
2. `package.json` の `"version": "1.0.0"` の数字を上げます(例: `"1.0.1"`)。
   **数字が同じままだと、更新として配られません。**
3. GitHubに更新したファイルをアップロードします(同じ名前で上書き)。
4. 「Actions」→「リリース」→「Run workflow」を押します。

数分後には、インストール済みのアプリが自動で新しい版を受け取ります。

- アプリを起動して5秒後と、その後1時間ごとに、新しい版がないか確認します。
- ダウンロードが終わると、画面下に「新しいバージョンの準備ができました」と出ます。
  「再起動して更新」を押すとすぐ切り替わります。押さずに終了しても、次に終了したときに自動で更新されます。
- インストーラーの更新は、変更のあった部分だけをダウンロードする方法(差分ダウンロード)が
  有効になっています。どれだけ小さくなるかは、更新の内容によります。
- 更新しても、保存フォルダのデータは消えません。
- Claude Code を使っている場合は、「ファイルを更新して、version(または ui-version)を上げて
  GitHubにpushして」と頼めば、①ならそれだけで配布まで終わります(②は最後の「Run workflow」だけ押します)。

## このパソコンで動かして確認したい場合(任意)

[Node.js](https://nodejs.org/) を入れたうえで、このフォルダで次を実行します。

```
npm install
npm start          ← アプリを起動して動作確認
npm test           ← 保存・画面パッチ・配線の自動テスト
npm run dist       ← このパソコンでインストーラーを作る(release フォルダに出力)
```

## 注意点

- Windows用です。Mac用も必要な場合は、`.github/workflows/release.yml` を拡張します(ご相談ください)。
- インストールと、更新の受け取りにはインターネットが必要です。それ以外は不要です。
- 自動更新が働くのは、インストールしたアプリだけです(`npm start` では働きません)。
- 更新の配布場所(GitHubのリポジトリ)が Public だと、アプリのプログラムは誰でも見られます。
  入力した記録は、各自のパソコンの保存フォルダにだけ保存され、GitHubには送られません。

## ファイル構成

```
package.json            アプリの設定・バージョン番号(更新のたびに version を上げる)
main.js                 アプリ本体(ウィンドウ・ファイル保存・自動更新)
storage.js              ファイル保存とバックアップの処理
patcher.js              画面だけの更新(パッチ)の受け取り・巻き戻しの処理
preload.js              画面とアプリ本体の橋渡し
renderer/index.html     画面(ツール本体)
build/icon.png          アプリのアイコン(好きな画像に差し替え可能・512px以上の正方形)
.github/workflows/      GitHubでインストーラーを自動作成する設定
test-*.js               自動テスト(保存 / 画面パッチ / アプリ本体の配線 / パッケージ内容)
```
